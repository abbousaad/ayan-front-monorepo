# AT-15 — Admin public orders management page

## Goal
Build the `/admin/public-orders` page that lists public orders with status filtering and provides status transition action buttons on each row.

## Requirements

### Page layout
- Title: "Public Orders"
- Status filter dropdown at the top with options: All, Pending, On Preparation, On Delivery, Paid
- A table using the shared `AdminTable` component to display orders
- Each row shows: Order ID (or a truncated version), Status (with a colored badge), and an Actions column

### Status badges
- `pending` -- yellow background (#fef9c3), dark yellow text (#713f12)
- `onpreparation` -- blue background (#dbeafe), dark blue text (#1e3a5f)
- `ondelivery` -- orange background (#ffedd5), dark orange text (#7c2d12)
- `paid` -- green background (#dcfce7), dark green text (#166534)

### Action buttons per row (contextual based on current status)
- When status is `pending`: show "Confirm" button (calls `confirmPublicOrder`)
- When status is `onpreparation`: show "Accept Delivery" button (calls `acceptPublicOrderDelivery`)
- When status is `ondelivery`: show "Mark Paid" button (calls `markPublicOrderPaid`)
- When status is `paid`: no action buttons (order is terminal)
- After any action succeeds, re-fetch the list to show updated data
- On error, show an alert banner at the top (red background, same style as admin-orders-page.tsx error messages)

### Data flow
1. On mount (and when filter changes), call `listPublicOrders(token, status)` to fetch orders
2. Display results in the table
3. Action buttons call the corresponding API function, then refresh the list
4. Show loading state while fetching

### Table columns
Display whatever fields the API returns. At minimum show these columns:
- **ID** -- the order `_id` or `id` field
- **Status** -- rendered as a badge
- **Created** -- if a date field exists (e.g. `createdAt`), format it as a readable date
- **Total** -- if a total/amount field exists
- **Actions** -- contextual action buttons

Since the API response schema is not fully documented, the component should gracefully handle missing fields (show "-" or omit columns if field is absent from the first response).
