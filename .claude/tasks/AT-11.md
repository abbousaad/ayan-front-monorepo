# AT-11 — Admin Change Password Screen + Flow

## Goal

Build the `/admin/change-password` page and ensure the `mustChangePassword` redirect flow works end-to-end.

## Requirements

### Page layout
- Title "Change Password"
- If `mustChangePassword` is true, show a yellow warning banner: "You must change your password before continuing."
- Form with 3 fields: Current Password, New Password, Confirm New Password
- "Change Password" button
- Success: redirect to `/admin` dashboard
- Error: show red error message (wrong current password, etc.)

### mustChangePassword flow
The `AdminAuthProvider` already stores `user.mustChangePassword`. The flow should be:
1. User logs in at `/admin/login`
2. If `user.mustChangePassword === true`, the login page redirects to `/admin/change-password`
3. On this page, after successful password change, update the user in auth context to set `mustChangePassword = false`
4. Redirect to `/admin`

**Check if the login page already handles the redirect.** If it does, this task only needs to build the change-password page itself. If not, also update the login page.

### Form validation (client-side)
- Current Password: required
- New Password: required, minimum 6 characters
- Confirm New Password: required, must match New Password
